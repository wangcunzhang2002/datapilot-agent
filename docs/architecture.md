# DataPilot 架构决策

## 为什么 SQL 由模板生成

当前版本的目标是展示 Agent 的执行闭环和验证机制，而不是声称一个小样本能安全覆盖任意 Text-to-SQL。规划节点可由结构化 LLM 在五种受支持意图中选择，也可使用离线规则基线；SQL 始终来自已审查模板，SQLite 边界再次验证只读语句和表白名单。模型响应无效或端点失败时会回退并计数。

这形成两层约束：规划器不能自由拼接写操作，工具层也不信任规划器。

## 为什么答案后还有验证节点

“SQL 能运行”不等于“口径正确”。地区、品类与月份汇总会把分组总额和源表总额比较，状态分析会比较分组计数与源表计数。验证不通过时，响应会保留失败状态，不能伪装成成功结果。

## 生产化扩展点

1. 用真实数据目录服务替代固定 Schema，并保留列级权限。
2. 将当前模板验证升级为 SQL AST 与查询成本策略，同时保留模型意图白名单。
3. 增加问题—SQL—结果人工标注集和模型版本对比。
4. 将 trace、token、时延和错误写入可观测平台。
5. 对高风险查询加入人工确认与资源预算。
